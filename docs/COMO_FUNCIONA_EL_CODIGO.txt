VETERINARIA ALEM - GUÍA PARA EDITAR
====================================

TECNOLOGÍAS
-----------
Este proyecto está hecho solamente con:
- HTML: estructura de las páginas.
- CSS: diseño, colores, tamaños y organización.
- PHP: formularios, sesiones, permisos y consultas.
- MySQL: base de datos.
- XAMPP: Apache + MySQL + phpMyAdmin.

NO UTILIZA JAVA NI JAVASCRIPT.


1. DISEÑO
---------
Todo el diseño principal está en:
css/estilos.css

Ahí puedes cambiar:
- colores
- tamaños
- botones
- tarjetas
- tablas
- formularios
- menú
- diseño para celular

2. MENÚ
-------
El menú está en:

El pie de página está en:

-------------------

Datos normales de XAMPP:

Base de datos: veterinariaalem


4. BASE DE DATOS
----------------
El SQL para importar está en:
sql/veterinariaalem.sql

En phpMyAdmin:
1. Enciende Apache y MySQL en XAMPP.
2. Abre phpMyAdmin.
3. Importa sql/veterinariaalem.sql.
4. Se creará la base veterinariaalem.


4B. SI YA TENÍAS LA BASE ANTERIOR IMPORTADA
-------------------------------------------
Importa sql/actualizacion_v2.sql (conserva tus datos). Si es una
instalación nueva, importa solamente sql/veterinariaalem.sql.

7. LOGIN Y SESIONES
-------------------
login.php recibe:
$_POST["email"]
$_POST["password"]

PHP busca el usuario en MySQL.

password_verify() comprueba la contraseña.

Si es correcta se guardan datos en:
$_SESSION["usuario_id"]
$_SESSION["nombre"]
$_SESSION["rol"]

auth.php comprueba si existe una sesión y si el usuario es administrador.


8. RELACIÓN ENTRE TABLAS
------------------------
Una mascota tiene un id_cliente.
Un turno tiene:
- id_cliente
- id_mascota
- id_empleado
- id_servicio

El historial tiene:
- id_mascota
- id_empleado

Estos IDs permiten relacionar las tablas.


9. CÓMO FUNCIONA EL PROYECTO

11B. NOVEDADES DE ESTA VERSIÓN
------------------------------
a) CONTACTO Y SOPORTE
   Los datos están en config.php (VET_TELEFONO, VET_EMAIL_SOPORTE) y se
   muestran en contacto.php, soporte.php, la portada y el pie de página.

b) CAPTCHA "NO SOY UN ROBOT"
   includes/captcha.php. Casilla obligatoria + campo trampa oculto +
   tiempo mínimo + token de un solo uso. Se usa en el registro y en todas
   las acciones del administrador. Sigue sin usar JavaScript.
   Para formularios nuevos: <?= captcha_html() ?> y if (!validar_captcha()).

c) CORREO DE VERIFICACIÓN
   Al registrarse se crea la cuenta como "sin verificar" y se envía un
   correo con un enlace que dura 24 horas (includes/mailer.php). Sin
   verificar no se puede iniciar sesión. El remitente es
   nahufontao14@gmail.com (config.php).
   Para que los correos salgan de verdad hay que completar SMTP_CLAVE en
   config.php con una "contraseña de aplicación" de Google (no la
   contraseña normal). Mientras esté vacía el sistema está en MODO
   DEMOSTRACIÓN: guarda los correos en /correos_enviados y muestra el
   enlace de verificación en pantalla para poder probar.

d) TIENDA Y FACTURA ELECTRÓNICA
   productos.php -> carrito.php -> factura.php. Al confirmar: se
   descuenta el stock, se guarda el pedido (tablas pedidos y
   pedido_items) y se crea la factura (tabla facturas) con número
   A-000001, A-000002... Los precios incluyen IVA (22%, configurable).
   La factura se envía por correo y queda en "Facturas". El pago es
   simulado y la factura es de demostración, sin validez fiscal.

e) citas PARA CLIENTES
   citas.php: el cliente elige mascota, servicio y veterinario, busca
   horarios libres (por fecha o los próximos disponibles) y reserva.
   Horario: 08:00 a 19:00, lunes a sábado, citas de 30 min
   (configurable en config.php). No permite dos citas en el mismo
   horario con el mismo veterinario.

f) PRIVACIDAD DE LOS CLIENTES
   Cada cliente ve solo SUS mascotas, citas, historial y facturas.
   Antes cualquier cliente podía ver los datos de todos. La política
   está en privacidad.php y hay que aceptarla al registrarse.


12. PARA EXPLICAR EN LA PREDEFENSA
----------------------------------
"HTML se utiliza para crear la estructura de las páginas.
CSS se utiliza para el diseño.
PHP procesa los formularios, las sesiones y los permisos.
MySQL almacena la información.
XAMPP permite ejecutar PHP y MySQL de forma local.

El login consulta el usuario en la base de datos y crea una
sesión. El rol determina qué puede hacer cada usuario.

Las tablas están relacionadas mediante IDs y claves foráneas."

ACTUALIZACION DE NOMENCLATURA Y MER
----------------------------------
- El módulo y la tabla de turnos se renombraron a citas.
- El módulo y la tabla de dueños se renombraron a clientes.
- El módulo y la tabla de veterinarios se renombraron a empleados.
- Las claves foráneas asociadas se actualizaron a id_cliente e id_empleado.
- Se agregó la tabla proveedores y el módulo administrativo proveedores.php.
- Los productos pueden asociarse a un proveedor mediante id_proveedor.
- Se agregaron a empleados, servicios e historial campos contemplados en el MER.

NOTA DE COMPATIBILIDAD:
El código PHP de esta versión conserva el campo técnico `id` como clave primaria
en las tablas existentes para no romper las consultas y formularios ya desarrollados.
Los nombres específicos de claves primarias del MER (por ejemplo ID_Mascota,
ID_Cliente, ID_Empleado, ID_Cita) todavía requieren una migración coordinada
de todas las consultas PHP antes de poder reemplazar físicamente esas columnas.
No cambies solamente el nombre de una PK en phpMyAdmin: se romperían relaciones
y consultas del sistema.


ROL DE EMPLEADO
---------------
- usuarios.rol ahora admite: admin, empleado, cliente.
- Para bases ya creadas: importar sql/actualizacion_v3_rol_empleado.sql.
  Instalación nueva: veterinariaalem.sql ya lo incluye.
- Cuenta de ejemplo: laura@veterinariaalem.com / empleado123.
- includes/auth.php: es_empleado(), es_personal() y exigir_empleado().
- includes/helpers.php: empleado_id_actual() une usuarios con empleados (empleados.id_usuario).
- Permisos del empleado (A=alta, B=baja, M=modificar, L=listar), definidos en includes/auth.php
  (permisos_empleado(), puede(), exigir_permiso()):
    Mis citas: L | Mascotas: A B M L | Historial: A B M L | Servicios: A B M L
    Tienda/Productos: A M L (sin baja) | Perfil: M
- Los módulos de mascotas, historial, servicios y productos se comparten con el admin (carpeta admin/);
  el empleado solo ve los botones permitidos. Carpeta empleado/: index.php (panel), citas.php, perfil.php.
- En el historial el empleado solo puede registrar historias a su propio nombre.
- Al cambiar un usuario a "empleado" en admin/usuarios.php se crea o vincula su ficha en empleados.
- Las páginas de cliente (citas, mascotas, historial, tienda, carrito, facturas, mi perfil)
  redirigen al empleado a su panel.
